# Plan: UART Communication Schema (MCU ↔ Raspberry Pi)

## Context
The Pillba dashboard runs on a Raspberry Pi and controls a pill dispenser whose actuators and sensors live on a microcontroller (MCU — e.g. Arduino/STM32). They communicate over a hardware UART serial link. This schema defines the wire format, every message type, and the payload layout so both sides can encode and decode reliably.

The UI already uses the following live data that must come from the MCU:
- Load sensor weight (filling flow)
- Compartment lid open/closed state
- Dispense confirmation (motor ran successfully)
- Schedule execution events (dose taken / missed)
- Device battery level & online status
- Compartment fill counts

And the Pi sends to the MCU:
- Dispense commands (medication slot + quantity)
- Schedule entries (slot, dose time, active flag)
- Settings (sound volume, alerts enable)
- Factory reset command

## Wire Format

### Frame structure (binary, little-endian)
```
┌────────┬────────┬──────────┬──────────┬─────────────────┬───────┐
│ 0xAA   │ 0x55   │ MSG_TYPE │ LENGTH   │ PAYLOAD         │ CRC8  │
│ 1 byte │ 1 byte │ 1 byte   │ 1 byte   │ 0–251 bytes     │ 1byte │
└────────┴────────┴──────────┴──────────┴─────────────────┴───────┘
```
- **Sync bytes** `0xAA 0x55` — unambiguous start-of-frame sentinel
- **MSG_TYPE** — single byte enum (see table below)
- **LENGTH** — byte count of PAYLOAD only (0–251)
- **CRC8** — CRC-8/MAXIM over bytes [MSG_TYPE, LENGTH, PAYLOAD...]
- Max total frame: 256 bytes
- UART settings: **115200 baud, 8N1**

### Framing on the Pi side (Python)
```python
SYNC = b'\xAA\x55'
HEADER_SIZE = 4   # sync(2) + type(1) + length(1)
FOOTER_SIZE = 1   # crc(1)

def encode_frame(msg_type: int, payload: bytes) -> bytes: ...
def decode_frame(raw: bytes) -> tuple[int, bytes]: ...  # raises on bad CRC
```

## Files to create

### `schema/uart_protocol.py`
Single source of truth for the Pi. Contains:
- `MsgType` IntEnum with all message IDs
- `struct` format strings for every payload
- `encode_frame` / `decode_frame` helpers
- One dataclass per message type (using `@dataclass` + `struct.pack/unpack`)

### `schema/uart_protocol.h` (C header, for MCU)
Mirror of the Python schema — packed C structs and `#define` constants the MCU firmware includes. Generated by hand to match byte-for-byte.

## Message type table

| ID   | Name                  | Dir       | Description |
|------|-----------------------|-----------|-------------|
| 0x01 | `HEARTBEAT`           | MCU→Pi    | Periodic alive ping + device vitals |
| 0x02 | `HEARTBEAT_ACK`       | Pi→MCU    | Acknowledge heartbeat |
| 0x10 | `DISPENSE_CMD`        | Pi→MCU    | Trigger dispense for a slot |
| 0x11 | `DISPENSE_RESULT`     | MCU→Pi    | Confirm dispense success/fail |
| 0x20 | `SCHEDULE_SET`        | Pi→MCU    | Write one schedule entry |
| 0x21 | `SCHEDULE_ACK`        | MCU→Pi    | Acknowledge schedule write |
| 0x30 | `DOSE_EVENT`          | MCU→Pi    | A scheduled dose was taken/missed |
| 0x40 | `LOAD_SENSOR`         | MCU→Pi    | Real-time weight reading during fill |
| 0x41 | `LID_STATUS`          | MCU→Pi    | Compartment lid opened or closed |
| 0x50 | `SETTINGS_SET`        | Pi→MCU    | Push settings to MCU |
| 0x51 | `SETTINGS_ACK`        | MCU→Pi    | Acknowledge settings write |
| 0x60 | `DEVICE_STATUS`       | MCU→Pi    | Battery, compartment fill bitmap |
| 0xF0 | `FACTORY_RESET`       | Pi→MCU    | Wipe MCU EEPROM |
| 0xFF | `ERROR`               | Both      | Error response with code + message |

## Payload definitions

### `0x01 HEARTBEAT` (MCU→Pi) — 4 bytes
```
battery_mv    : uint16   # millivolts (e.g. 3820 = 3.82V → ~94%)
status_flags  : uint8    # bit 0=wifi_ok, bit 1=bt_ok, bit 2=rtc_ok
compartments  : uint8    # bitmask, bit N=1 means compartment N+1 has pills
```

### `0x02 HEARTBEAT_ACK` (Pi→MCU) — 4 bytes
```
unix_time     : uint32   # Pi system time, MCU uses to sync RTC
```

### `0x10 DISPENSE_CMD` (Pi→MCU) — 2 bytes
```
slot          : uint8    # compartment number 1–8
quantity      : uint8    # number of pills (1–5)
```

### `0x11 DISPENSE_RESULT` (MCU→Pi) — 3 bytes
```
slot          : uint8
quantity_dispensed : uint8   # actual pills released (from motor encoder)
result        : uint8        # 0x00=ok, 0x01=jam, 0x02=empty, 0x03=timeout
```

### `0x20 SCHEDULE_SET` (Pi→MCU) — 5 bytes
```
slot          : uint8    # compartment 1–8
hour          : uint8    # 0–23
minute        : uint8    # 0–59
days_mask     : uint8    # bitmask Mon=bit0 … Sun=bit6
active        : uint8    # 0=disabled, 1=enabled
```

### `0x21 SCHEDULE_ACK` (MCU→Pi) — 2 bytes
```
slot          : uint8
result        : uint8    # 0=ok, 1=invalid slot, 2=flash write error
```

### `0x30 DOSE_EVENT` (MCU→Pi) — 4 bytes
```
slot          : uint8
unix_time     : uint32   # timestamp of event (MCU RTC)
status        : uint8    # 0=taken, 1=missed, 2=manual
```
*Note: total 6 bytes — struct `<BIB`*

### `0x40 LOAD_SENSOR` (MCU→Pi) — 3 bytes
```
compartment   : uint8
weight_g      : uint16   # grams × 10 (e.g. 152 = 15.2g), fixed-point
```

### `0x41 LID_STATUS` (MCU→Pi) — 2 bytes
```
compartment   : uint8
state         : uint8    # 0=closed, 1=open
```

### `0x50 SETTINGS_SET` (Pi→MCU) — 3 bytes
```
volume        : uint8    # 0–100
refill_alert  : uint8    # 0=off, 1=on
timezone_offset_min : int16  # minutes from UTC (e.g. 330 = UTC+5:30)
```

### `0x51 SETTINGS_ACK` (MCU→Pi) — 1 byte
```
result        : uint8    # 0=ok, 1=error
```

### `0x60 DEVICE_STATUS` (MCU→Pi) — 4 bytes
```
battery_pct   : uint8    # 0–100
wifi_rssi     : int8     # dBm (negative), 0 if not applicable
compartments_filled : uint8   # count of non-empty compartments (0–8)
error_flags   : uint8    # bit field of active hardware faults
```

### `0xF0 FACTORY_RESET` (Pi→MCU) — 2 bytes (confirmation token)
```
confirm_token : uint16   # must equal 0xDEAD or MCU ignores it
```

### `0xFF ERROR` (Both) — 2 bytes
```
error_code    : uint8    # see error code table in uart_protocol.py
context_byte  : uint8    # e.g. slot number that caused the error
```

## Error codes
```python
class ErrorCode(IntEnum):
    UNKNOWN        = 0x00
    BAD_CRC        = 0x01
    BAD_LENGTH     = 0x02
    UNKNOWN_MSG    = 0x03
    SLOT_INVALID   = 0x10
    MOTOR_JAM      = 0x11
    COMPARTMENT_EMPTY = 0x12
    FLASH_ERROR    = 0x20
    RTC_FAULT      = 0x21
```

## Connection to the React prototype
`uart_protocol.py` lives alongside the Qt app. The UI is updated by reading live MCU messages:
- `HEARTBEAT` → updates battery %, online dot, compartment fill count on Home
- `LOAD_SENSOR` → drives the fill-level bar in the Add Medication flow
- `LID_STATUS` → confirms lid open before enabling "Start filling" button
- `DOSE_EVENT` → appends entries to the activity log
- `DISPENSE_RESULT` → shows success/fail banner on Manual Dispense page

## Verification
1. Write a loopback test script: connect Pi UART TX→RX, send every message type, assert round-trip decode matches encode.
2. Verify CRC catches single-bit flips by flipping one payload byte and confirming `decode_frame` raises.
3. Confirm all struct sizes match the LENGTH field constants in the C header with a `static_assert` on the MCU side.

# Plan: Pill Dispenser Dashboard Prototype

## Context
Build a React prototype that faithfully simulates the look and interaction of a 320×480 Qt/Python touchscreen UI for an automated pill dispenser running on a Raspberry Pi. Because this is a visual prototype in Figma Make (React), the output is a fixed 320×480px container centered in the browser viewport — not actual Qt code. The design should feel like an embedded medical device UI: trustworthy, clinical-clean, and touch-friendly.

## Aesthetic stance
- **Stance**: Clinical-geometric — memphis-inspired grid structure, restrained for a medical context. Structured, clear, no unnecessary decoration.
- **Font**: Nunito (Google Fonts) — geometric, rounded, highly readable at small sizes on a touchscreen. Used for all text.
- **Colors**:
  - Background: `#F8FAFC` (near-white)
  - Sidebar: `#0F172A` (deep navy) 
  - Primary: `#0D9488` (teal — trustworthy, clinical)
  - Primary foreground: `#FFFFFF`
  - Card: `#FFFFFF`
  - Accent: `#14B8A6` (bright teal for active states)
  - Muted: `#E2E8F0`
  - Muted foreground: `#64748B`
  - Border: `rgba(15,23,42,0.1)`
  - Destructive: `#EF4444`
  - Chart colors: teal scale + amber + red

## Files to modify

### `src/styles/fonts.css`
Add Google Fonts import for Nunito (weights 400, 500, 600, 700).

### `src/styles/theme.css`
Update `:root` token values to match the clinical-teal palette above. Preserve all token names and the `@theme inline` block unchanged.

### `src/app/App.tsx`
Replace placeholder with the full dashboard. All logic, state, and components live in this single file.

## Layout structure

Fixed container `w-[320px] h-[480px]` centered in the viewport with `overflow-hidden`. Inside:

```
┌──────────────────────────────────┐
│  Top bar: [← Back] [Page Title]  │  (hidden on Home)
├──────────────────────────────────┤
│                                  │
│         Page content             │
│                                  │
│                                  │  480px
└──────────────────────────────────┘
        320px
```

**Navigation model**: Home page is the hub. Each of the 4 nav cards navigates to its page. On sub-pages, a top bar shows a `←` back button (top-left, `ArrowLeft` lucide icon) and the page title centered. Tapping back always returns to Home. No sidebar.

## Pages (5 views, state-driven routing)

### 1. Home (default)
- Header: "MediDose" wordmark + current time (live clock via `useState`/`useEffect`)
- 2×2 grid of large nav cards, each with:
  - Icon (lucide-react)
  - Title
  - Subtitle/description
  - Full `rounded-xl` white card with teal left-border accent
- Cards: "View Schedule", "Manual Dispense", "View Log", "Device Settings"
- Clicking a card navigates to that page

### 2. View Schedule
- Header: "Schedule"
- List of 4–5 medication entries, each card row showing:
  - Pill icon, medication name, dose
  - Time badge
  - Toggle switch (active/inactive state)
- A small inline `recharts` `AreaChart` showing weekly doses (7 data points, teal fill)
- "Add Medication" primary button at bottom

### 3. Manual Dispense
- Header: "Manual Dispense"
- Form card:
  - Select medication (styled select input, `bg-input-background`)
  - Quantity stepper (− / count / + buttons)
  - Confirm toggle switch: "Confirm manual override"
- Large primary "Dispense Now" button
- Warning note with destructive color

### 4. View Log
- Header: "Activity Log"
- `recharts` `BarChart` showing last 7 days (chart-1 teal bars, chart-5 amber for missed)
- Scrollable log list (last 5 events) with timestamp, medication, status badge (success/missed/manual)

### 5. Device Settings
- Header: "Settings"
- Grouped settings list:
  - Wi-Fi toggle switch
  - Bluetooth toggle switch
  - Refill alert toggle switch
  - Sound input (volume slider styled as range)
  - Timezone selector
  - "Factory Reset" destructive button

## Component patterns

**Top bar** (sub-pages only): `flex items-center h-12 px-3 bg-sidebar text-sidebar-foreground`. Back button: `ArrowLeft` icon in a `w-9 h-9 rounded-lg` tappable area. Page title centered.

**Cards**: `bg-card rounded-xl border border-border shadow-sm p-3`.

**Buttons (primary)**: `bg-primary text-primary-foreground rounded-lg px-4 py-2.5 font-medium text-sm active:opacity-80`.

**Buttons (secondary)**: `bg-secondary text-secondary-foreground rounded-lg px-4 py-2.5`.

**Switch**: Custom toggle built with a `div` + conditional `translateX` for thumb, `bg-switch-background` off / `bg-primary` on.

**Input**: `bg-input-background text-foreground rounded-lg px-3 py-2 border border-border text-sm`.

**Modal dialog**: `bg-popover text-popover-foreground rounded-xl border border-border shadow-lg`. Triggered on "Dispense Now" for a confirmation step.

## State management
Single `useState<Page>` for routing. Per-page local state for switches, form values, modal visibility. Live clock via `useEffect` with `setInterval` in Home.

## Fonts wiring
Import Nunito from Google Fonts in `src/styles/fonts.css`. Set `--font-size: 14px` in theme (slightly smaller than default 16px to fit 320px width), and apply `font-family: 'Nunito', sans-serif` on `body` in theme.css `@layer base`.

## Verification
After implementation: confirm the 320×480 container renders centered, all 5 pages navigate correctly via sidebar + card taps, switches toggle, the BarChart and AreaChart render, the dispense confirmation modal opens/closes, and the live clock updates.
